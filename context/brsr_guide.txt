================================================================================
                    GREENLEDGER ESG SERVER — SEBI BRSR GUIDE
              Comprehensive Backend Changes & API Integration Guide
================================================================================

1. EXECUTIVE NOTICE: MIGRATION TO NEW 41-PAGE SEBI BRSR STATUTORY ENGINE
--------------------------------------------------------------------------------
The backend has completed a major statutory upgrade. We have officially switched 
from the previous segregated, partial disclosures to the complete, official 
41-page statutory SEBI Business Responsibility and Sustainability Reporting (BRSR) 
Annexure II framework.

Because of this statutory expansion:
- The previous frontend UI (which only had isolated sections for Energy, Water, 
  Waste, and Air) is superseded.
- The frontend will be rebuilt from scratch in a pixel-perfect, cohesive format 
  conforming to the complete statutory SEBI Annexure II framework.
- All historical activities (fuel, electricity) remain fully intact and automatically 
  power the energy and GHG emission intensity calculations under Principle 6.
- All other statutory sections now have dedicated database persistence models, 
  repositories, schemas, services, and REST APIs.

--------------------------------------------------------------------------------
2. CONCEPTUAL UI STRUCTURE (HIGH-LEVEL DESIGN FOR FRONTEND)
--------------------------------------------------------------------------------
The frontend design should follow a "Two-Tier / Contextual Nested Workspace" model:

A. Primary Main Navigation Sidebar:
   - Contains a single, clean entry point: [ 📊 BRSR ] or [ 📊 BRSR Reporting ].
   - Clicking this opens the dedicated BRSR Filing Workspace.

B. Contextual Inner Secondary Sidebar (The Subtle Filing Rail):
   - Appears inside the BRSR page.
   - Provides smooth, organized navigation across all statutory sections:
     ├── 📋 Filing Overview / Dashboard
     ├── 🏢 Section A: General Disclosures
     │     ├── Entity Details & Operations
     │     ├── Employees, Workers & Diversity
     │     └── CSR & Stakeholder Complaints
     ├── 📜 Section B: Management & Process
     │     ├── NGRBC Principles 1–9 Policy Matrix
     │     └── Governance, Oversight & Review
     ├── 🌿 Section C: Environmental Performance (Principle 6)
     │     ├── ⚡ Energy Consumption & Intensity (Essential 1 & 2)
     │     ├── 💧 Water Disclosures & ZLD (Essential 3, 4, 5)
     │     ├── 💨 Air Stack Emissions (Essential 6)
     │     ├── 🌍 GHG Scope 1 & 2 Disclosures (Essential 7 & 8)
     │     ├── 🗑️ Waste Management & Recovery (Essential 9 & 10)
     │     └── 🌲 Sensitive Ecology & EIA Projects (Essential 11, 12, 13)
     ├── ⚖️ Section C: Social & Governance (Principles 1–5, 7–9)
     │     ├── P1: Ethics, Bribery & Fines
     │     ├── P2: Sustainable Products & LCA

     │     ├── P8: Inclusive Growth & Social Impact
     │     └── P9: Consumer Value & Privacy
     └── 📑 Review & Master PDF Export (41-Page Packet)

C. Persistent Header:
   - Reporting Period Selector (e.g., FY 2024-25, loaded via reporting period API).
   - Real-time Completion Progress Bar (% calculated from section completion).
   - Global Action Buttons: [Save Draft], [Live PDF Preview], [Submit for Verification].

D. Side-by-Side Live PDF Viewer:
   - Built directly into the Review/Export tab, previewing the binary PDF stream 
     generated by the backend `/full-report/pdf` endpoint.

--------------------------------------------------------------------------------
3. WHAT BACKEND CHANGES WERE MADE? (CONTEXT FOR FRONTEND)
--------------------------------------------------------------------------------
1. Database Schema & Persistence Layer:
   - Created dedicated PostgreSQL tables:
     • `brsr_section_a_disclosures` (Section A General Disclosures)
     • `brsr_section_b_disclosures` (Section B Policy & Governance)
     • `brsr_section_c_general_disclosures` (Section C Principles 1, 2, 3, 4, 5, 7, 8, 9)
     • `brsr_statutory_disclosures` (Principle 6 PAT, ZLD, Sensitive Areas, EIA, Compliance)
     • `brsr_water_disclosures` (Principle 6 Water withdrawal, consumption, discharge)
     • `brsr_waste_disclosures` (Principle 6 9-category Waste matrix, recovery, disposal)
     • `brsr_air_disclosures` (Principle 6 Stack air emissions NOx, SOx, PM, CO)
   - Every single disclosure is scoped by `(tenant_id, reporting_period_id)`.
   - Single-source-of-truth upsert semantics: saving a section updates the existing 
     record for that fiscal year without creating orphan records.

2. Automated Calculation Engine:
   - Principle 6 Energy and Scope 1 & 2 GHG figures are pre-calculated directly 
     from logged fuel and electricity activity rows.
   - Intensity ratios (per INR turnover, per INR Crore, per physical output) are 
     automatically derived using Python Decimal arithmetic.

3. Complete PDF Generation Engine:
   - Built high-speed PDF generation engine (using `fpdf2` with TrueType Unicode fonts).
   - Generates the exact 41-page statutory filing packet matching SEBI Annexure II.
   - Endpoints serve binary `application/pdf` streams with `Content-Disposition`.

4. AUTHENTICATION & GLOBAL HEADERS
--------------------------------------------------------------------------------
All BRSR endpoints require Tenant User authentication.

Headers required on every request:
  Authorization: Bearer <access_token>
  Content-Type: application/json (for GET / PUT / POST with JSON body)

Standard Envelope:
All JSON endpoints return the standardized `APIResponse[T]` structure:
{
  "success": true,
  "status_code": 200,
  "message": "Operation successful",
  "data": { ... },
  "error": null,
  "method": "GET",
  "path": "/api/v1/tenant/brsr/...",
  "timestamp": "2026-11-13T15:00:00Z"
}

On error (e.g. 400, 404, 422):
{
  "success": false,
  "status_code": 422,
  "message": "Validation error",
  "data": null,
  "error": {
    "error_code": "VALIDATION_ERROR",
    "detail": "Field required",
    "validation": [
      {
        "loc": ["body", "reporting_period_id"],

      }
    ]
  },
  "method": "PUT",

}

================================================================================
6. KEY VALIDATION & DATA TYPE CONSTRAINTS
================================================================================
1. Financial Turnover & Currencies:
   - Always in INR (Indian Rupees) as numbers/floats or strings for precision.
   - For intensity metrics, backend automatically computes both `per INR` and 
     `per INR Crore` (1 Crore = 10,000,000 INR).

2. Enums:
   - `status`: Allowed values are `"draft"`, `"submitted"`, `"verified"`, `"approved"`, `"rejected"`.
   - Default is `"draft"`.

3. Soft-Deletes:
   - All queries filter `is_deleted == false`.

4. Dynamic Rows:
   - Lists such as `business_activities`, `products_sold`, `policy_matrix`, 
     `commitments_and_goals`, `stacks`, and `ghg_reduction_details` can be dynamically 
     appended/removed by the frontend.
