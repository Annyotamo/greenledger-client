1. GLOBAL ARCHITECTURE & CONVENTIONS
================================================================================

1.1 Standard Response Envelope (APIResponse[T])
------------------------------------------------
Every single API response emitted by the server (whether 200, 201, 400, 404, 422,
or 500) wraps its payload in the standardized GreenLedger `APIResponse[T]` format:

{
  "success": true,               // boolean: true for 2xx codes, false for 4xx/5xx
  "status_code": 200,            // integer: HTTP status code
  "message": "Operation message",// string: Human-readable status description
  "data": { ... } | [ ... ] | null, // generic payload or null on deletion/error
  "error": null,                 // null on success, or APIError object on error
  "method": "POST",              // string: HTTP method executed
  "path": "/api/v1/tenant/lwg/production", // string: Request path
  "timestamp": "2026-11-24T09:15:30.123456Z" // string: ISO-8601 UTC timestamp
}

1.2 Standard Error Structure (APIError)
----------------------------------------
When `success` is false, `data` is null and `error` contains structured diagnostics:

{
  "success": false,
  "status_code": 422,
  "message": "Month '2023-01-01' is outside the 24-month audit window (2024-11-01 to 2026-10-31).",
  "data": null,
  "error": {
    "error_code": "LWG_MONTH_OUTSIDE_WINDOW",
    "detail": "Month '2023-01-01' is outside the 24-month audit window (2024-11-01 to 2026-10-31).",
    "validation": null // array of field validation objects on 422 RequestValidationError
  },
  "method": "POST",
  "path": "/api/v1/tenant/lwg/production",
  "timestamp": "2026-11-24T09:15:30.123456Z"
}

When Pydantic request validation fails, `error.validation` provides an array of:
[
  {
    "loc": ["body", "output_quantity"],
    "msg": "Input should be greater than or equal to 0",
    "type": "greater_than_equal"
  }
]

1.3 Authentication & Authorization Headers
-------------------------------------------
- Header: `Authorization: Bearer <access_jwt_token>`
- Token claims verified by backend:
  - `sub`: User ID
  - `tenant_id`: Scoped Tenant ID (enforces strict multi-tenant isolation)
  - `sid`: UserAuthSession identifier (verified not revoked)
- Permissions:
  - All `GET` endpoints require read permission: `require_read(FeatureKey.LWG)`
  - All `POST`, `PUT`, `DELETE` endpoints require write permission: `require_write(FeatureKey.LWG)`
  - Default permitted roles: `TENANT_ADMIN`, `TENANT_OWNER`, `ESG_TEAM`. Read-only: `AUDITOR`, `FACILITY_HEAD`.

1.4 Decimal & Number Serialization Rules
-----------------------------------------
- All environmental metrics (energy quantities, volumes, areas, GJ, intensities)
  are calculated using pure Python Decimal arithmetic to eliminate binary float rounding drift.
- In JSON responses, Decimal values are serialized as formatted numeric decimals or strings
  (e.g., `36.0`, `9290.3`, `65.9`).
- The frontend should parse them via `parseFloat(val)` or `Number(val)` for display or charts.

1.5 Date Formats
-----------------
- Monthly records use the first calendar day of the month: `"YYYY-MM-01"` (e.g. `"2025-03-01"`).
- ISO-8601 UTC strings for creation and update timestamps: `"2026-11-24T08:30:00Z"`.


================================================================================
2. DOMAIN ENUMS & ALLOWED VALUE DICTIONARIES
================================================================================

2.1 LwgStage (Tannery Production Stages)
----------------------------------------
Specifies the production stages operated by the facility:
- "stage_1_raw_to_wetblue"        : Stage 1: Raw hide to Wet Blue (tanning)
- "stage_2_wetblue_to_crust"       : Stage 2: Wet Blue to Crust (re-tanning)
- "stage_3_crust_to_finish"        : Stage 3: Crust to Finished Leather (finishing)
- "stage_1_to_3_raw_to_finish"     : Stage 1 to 3: Fully Integrated Tannery
- "stage_2_to_3_wetblue_to_finish" : Stage 2 to 3: Processing from Wet Blue to Finish

*Note*: Per LWG Section 10/11 rules, when calculating facility-wide Energy and
Water intensity, the denominator production stage used is:
  1. `stage_3_crust_to_finish` (if run at the facility), or
  2. `stage_2_wetblue_to_crust` (if no finishing), or
  3. `stage_1_raw_to_wetblue` (beamhouse only).

2.2 LwgDepartmentStage (Department Categorization)
--------------------------------------------------
- "stage_1" : Allocated strictly to Stage 1 operations
- "stage_2" : Allocated strictly to Stage 2 operations
- "stage_3" : Allocated strictly to Stage 3 operations
- "common"  : Common / Site-wide infrastructure (ETP, Boiler, Admin, Utilities)

2.3 LwgOutputUnit (Leather Area Units)
--------------------------------------
- "sq_ft" : Square feet (standard commercial trade unit in India/Asia)
- "m2"    : Square meters (official LWG protocol metric unit)
*Conversion factor*: 1 m² = 10.7639 sq ft (1 sq ft = 0.092903 m²).

2.4 LwgEffluentType (Effluent Treatment Configurations)
-------------------------------------------------------
- "direct_discharge_own_etp" : Facility operates an on-site full ETP with treated discharge
- "discharge_to_cetp"        : Pre-treated effluent discharged to Common ETP (CETP)
- "both"                     : Combined on-site treatment and CETP connection

2.5 LwgInputMaterial (Material Classification)
----------------------------------------------
- "raw_hide_skin" : Raw animal hides / skins (salted, fresh)
- "wet_blue"      : Chrome tanned wet blue leather
- "wet_white"     : Chrome-free wet white leather
- "crust"         : Dried crust leather ready for finishing

2.6 LwgEnergySource (Energy Source Taxonomy)
--------------------------------------------
Grid & Fossil Sources:
- "grid_electricity" : State / municipal power grid
- "diesel_hsd"       : High Speed Diesel for generators/boilers
- "furnace_oil"      : Heavy Fuel Oil / Furnace oil
- "natural_gas_png"  : Piped Natural Gas
- "lpg"              : Liquefied Petroleum Gas
- "coal"             : Industrial coal

Renewable Energy Sources (Counted toward Renewable Energy Share %):
- "solar_onsite"                     : On-site rooftop or ground-mount solar PV (is_onsite=True, is_renewable=True)
- "purchased_renewable_electricity"  : Off-site green tariff or Power Purchase Agreement (PPA) (is_onsite=False, is_renewable=True)
- "biomass_or_briquettes"            : Agricultural briquettes, wood pellets, or biomass (is_onsite=True, is_renewable=True)

2.7 LwgEnergyUnit (Allowed Measurement Units)
---------------------------------------------
- "kwh"    : Kilowatt-hours (Electricity)
- "mwh"    : Megawatt-hours (Large electricity)
- "litres" : Litres (Liquid fuels: Diesel, Furnace Oil, LPG)
- "tonnes" : Metric tonnes (Solid fuels: Coal, Biomass briquettes)
- "kg"     : Kilograms (LPG cylinders, chemicals)
- "scm"    : Standard cubic meters (Natural Gas PNG)
- "gj"     : Gigajoules (Direct heat / steam)

2.8 Energy Source to Unit Mapping Matrix
-----------------------------------------
The API strictly validates unit compatibility upon POST/PUT:
| Energy Source                     | Allowed Units          | Multiplier to GJ (std) |
|-----------------------------------|------------------------|------------------------|
| grid_electricity                  | kwh, mwh               | 0.0036 per kWh         |
| purchased_renewable_electricity   | kwh, mwh               | 0.0036 per kWh         |
| solar_onsite                      | kwh, mwh               | 0.0036 per kWh         |
| diesel_hsd                        | litres                 | 0.0386 per Litre       |
| furnace_oil                       | litres                 | 0.0418 per Litre       |
| natural_gas_png                   | scm                    | 0.0385 per SCM         |
| lpg                               | kg, litres             | 0.0461 per kg / 0.026  |
| coal                              | tonnes                 | 20.0000 per Tonne      |
| biomass_or_briquettes             | tonnes                 | 15.0000 per Tonne      |

2.9 LwgWaterSource (Water Intake Classifications)
-------------------------------------------------
Fresh Water Sources:
- "borewell"            : Ground water extraction (Borewell / Tube well) -> Requires meter_id
- "municipal_supply"    : Piped municipal / corporation water -> Requires meter_id
- "tanker"              : Purchased private tanker water
- "rainwater_harvested" : Harvested on-site rainwater

Recycled Water Sources (Counted toward Recycled Water Share %):
- "recycled_own_etp" : Treated effluent recycled from on-site ETP / RO plant
- "recycled_cetp"    : Treated water received back from CETP

2.10 LwgDocumentType (Evidence Vault Document Classifications)
--------------------------------------------------------------
- "consent_to_operate"            : State Pollution Control Board Consent (Air/Water) -> Requires expiry_date
- "hazardous_waste_authorisation" : SPCB Hazardous Waste Authorization -> Requires expiry_date
- "electricity_bill"              : Monthly utility power bill
- "fuel_invoice"                  : Fuel purchase delivery challan or invoice
- "meter_photo"                   : Photographic proof of water/energy meter reading
- "lab_report"                    : ETP discharge or test lab analysis report
- "other"                         : Other supporting audit evidence

2.11 LwgMedalRating (Audit Medal Tiers & Scoring Thresholds)
------------------------------------------------------------
- "gold"    : Score >= 85.0%
- "silver"  : Score >= 75.0% and < 85.0%
- "bronze"  : Score >= 65.0% and < 75.0%
- "audited" : Score >= 50.0% and < 65.0%
- "fail"    : Score < 50.0%

2.12 LwgSectionStatus (Audit Readiness Statuses)
------------------------------------------------
- "ready"       : Data completeness 100%, valid permits attached, no critical gaps (Green)
- "gaps"        : Data entered but contains missing months, missing meter IDs, or expiring permits (Amber/Red)
- "not_started" : No data entered for this section in the 24-month window (Gray)
- "not_in_mvp"  : Protocol section outside current MVP tracking (Sections 1, 2, 3, 6, 7, 8, 9, 12, 13, 14, 15, 16, 17)

2.13 LwgGapSeverity (Deficiency Alert Levels)
---------------------------------------------
- "red"   : Critical compliance failure (e.g., missing production data for a month, missing water meter ID, expired SPCB consent).
- "amber" : Warning or quality issue (e.g., unmetered water source, purchased green power without PPA uploaded, permit expiring within 60 days).

2.14 LwgSectionNumber (All 17 LWG Protocol Sections)
----------------------------------------------------
Section 1 : General Information (Non-critical, Non-scoring)
Section 2 : Traceability: Subcontracted Operations (Critical)
Section 3 : Social Audit (Non-critical)
Section 4 : Operating Permits & Environment Approvals (Critical, MVP Section)
Section 5 : Production Data (Critical, MVP Section)
Section 6 : Incoming Traceability (Non-critical)
Section 7 : Outgoing Traceability (Non-critical)
Section 8 : Environmental Management Systems (Critical)
Section 9 : Restricted Substances & Compliance (Critical)
Section 10: Energy Consumption (Critical, MVP Section)
Section 11: Water Usage (Critical, MVP Section)
Section 12: Air & Noise Emissions (Critical)
Section 13: Waste Management (Critical)
Section 14: Effluent Treatment (Critical)
Section 15: Health, Safety & Emergency Preparedness (Critical)
Section 16: Chemical Management & Storage (Critical)
Section 17: Operations & Housekeeping (Critical)

*Critical Section Rule*: The facility's overall medal is capped at the MINIMUM
medal achieved across any CRITICAL section. (Non-critical sections do not drag down
the medal).

================================================================================
5. CORE BUSINESS LOGIC & CONVERSION RULES
================================================================================

5.1 The 24-Month Audit Data Window
-----------------------------------
- The LWG Protocol Issue 7 requires exactly 24 continuous calendar months of audited data.
- The 24 months are partitioned into two 12-month periods:
  - Previous 12 Months (P12): Months 1 through 12 of the window.
  - Latest 12 Months (L12)  : Months 13 through 24 of the window.
- The window is defined by `data_window_start` (first day of Month 1) and `data_window_end`
  (last day of Month 24).
- Logging data outside this window triggers `LwgMonthOutsideWindowException`.

5.2 Leather Area Normalization
------------------------------
- Input values in square feet are normalized: `Area_m2 = Area_sqft * 0.092903`
- Input values in square meters are normalized: `Area_sqft = Area_m2 * 10.7639`
- Both fields (`output_quantity_m2`, `output_quantity_sqft`) are stored in the DB row
  and returned in responses.

5.3 Energy & Water Intensity Math
----------------------------------
- Energy Intensity ($MJ/m²$):
  $$Intensity_{Energy} = \frac{\text{Total Energy in GJ} \times 1000}{\text{Denominator Stage Area in } m²}$$
- Water Intensity ($L/m²$):
  $$Intensity_{Water} = \frac{\text{Total Fresh Water in } m³ \times 1000}{\text{Denominator Stage Area in } m²}$$
- Year-over-Year (YoY) Change %:
  $$YoY\% = \frac{Intensity_{L12} - Intensity_{P12}}{Intensity_{P12}} \times 100$$
- A NEGATIVE YoY percentage means intensity decreased (efficiency improved), marked as
  `is_favorable = true` (Green).

5.4 Renewable & Recycled Share
------------------------------
- Renewable Energy Share %:
  $$Share_{Renewable} = \frac{GJ_{\text{solar}} + GJ_{\text{purchased renewable}} + GJ_{\text{biomass}}}{\text{Total Energy } GJ} \times 100$$
- Recycled Water Share %:
  $$Share_{Recycled} = \frac{Volume_{\text{own ETP}} + Volume_{\text{CETP recycled}}}{\text{Total Water Intake } m³} \times 100$$
